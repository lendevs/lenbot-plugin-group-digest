# group_digest

LenBot 的独立插件，需要 LenBot >=0.2,<1、Python >=3.13。

## 安装

在「能力 → 插件」填写 `https://github.com/lendevs/lenbot-plugin-group-digest`，准备后填写配置并应用，再选择启用的群。也可以下载仓库 ZIP 导入。插件名称仍为 `group_digest`，从旧内置版迁移时先更新到已移除内置插件的宿主，再安装同名插件；保持原来的参数、选群与数据目录。

群聊总结和长工作委派。在「插件」页启用，并选择在哪些群使用。

## 每日总结卡片

把过去一段时间（默认 24 小时，也可指定起止时间）的聊天做成一张卡片发到群里：消息数、发言人数、24 小时活跃分布、说话最多的人、聊了哪些话题，以及几句原话。

三种触发方式：

- **定时**：在「每天自动发总结的群」里选群，到「每天几点发」（默认 22:00，按群的时区）自动发。默认不选任何群。
- **命令**：`/群日报`，或 `/群日报 6` 总结最近 6 小时（1–72）。
- **自然语言**：插件注册工具 `group_summary_card`，角色允许它和 `tool_search` 后，Bot 可根据聊天里的时间要求调用。过去 12 小时用 `hours=12`，今天下午或某一天用 `start_at`、`end_at`；无时区的 ISO 日期时间按本群时区解释。两个模式不能混用，最多 72 小时。默认不填参数时总结过去 24 小时。

生成在后台进行，不阻塞聊天。聊天记录按「每批读多少字」（默认 12000 字）分批交给模型，每批一次调用，最后再合并一次；只有一批时只调用一次。模型用「总结用的模型」选的用途绑定。卡片上的原话直接取自消息记录，不用模型复述的文字。

不计入的消息：发给 Bot 的 `/` 命令、撤回的、发送失败的；少于 5 条时不生成。

卡片需要中文字体。留空「卡片字体」时依次找系统里的 PingFang、冬青黑体、Noto Sans CJK、文泉驿和微软雅黑；Docker 宿主镜像自带 Noto Sans CJK。

插件发出的卡片和文字不会被整理进长期记忆。

## 增量模式

默认关闭。在「每小时增量整理的群」选择目标群，并在这些群启用插件。每小时整理已结束时段的新消息，只保存独立小时摘要，不发送日报。首次运行补齐缓存保留期内已有消息；会调用所选模型并消耗 token。

摘要保存在本插件的 KV 中，默认保留 3 天。请求日报时复用完全包含在所选范围内的小时摘要；不完整小时重新读取原消息整理，避免混入范围外话题。消息新增或撤回会使对应小时重新整理。统计和原话仍以当前消息记录为准，摘要不会进入长期记忆。

最终卡片仍需要一次模型调用来合并话题。首次开启、缓存缺失或范围边缘有消息时，会有额外整理调用。重启或单插件重载保留缓存；停用／卸载保留插件数据，明确删除插件数据才会清空。

工具调用示例：

```json
{"hours": 12}
```

```json
{"start_at": "2026-10-06T12:00:00+08:00", "end_at": "2026-10-06T17:30:00+08:00"}
```

日期和时间由聊天模型结合用户要求、当前时间和群时区确定，插件不猜「昨天」是自然日还是过去 24 小时。返回后后台生成卡片；工具不接受其他群的目标参数。

## 其他命令

- `/群总结 只列已经决定的安排`：读取最近 `message_limit` 条消息（默认 50，1–100），生成一次文字总结直接回复。
- `/群工作 把刚才的活动安排做成 CSV`：以真实发送者的权限委派后台任务，最近的消息作为背景。需要任务环境、本群任务开关和发送者的任务权限。

附带只读 `group-digest` 技能，插件在本群启用、角色允许此技能后，后台任务可以读取它。

## 开发与验证

在仓库目录使用已安装 LenBot 的 Python 环境执行：

```sh
uv run --project /path/to/LenBot --no-sync pytest -q -c pyproject.toml tests
```

测试使用合成消息和本机服务，不调用真实模型、不发送 QQ 消息。

## 工具接口

工具采用接口 1 的显式简介、Field 参数说明与 `prompts/tools.md` 共享指南，返回原生 JSON 或文本。用 `PluginTest.preview_tools()` 查看模型说明、参数与可用性；模型服务默认关闭，真实发送仍单独核对。兼容和更新事项见 [CHANGELOG](CHANGELOG.md)。

CI 固定到包含当前插件接口的宿主开发提交；本次未创建版本标签或 Release。catalog-entry.json 只记录开发安装来源，未公开插件不加入主目录。

本机生成 ZIP（LenBot 仓库与本仓库放在同一目录下）：`uv run --no-project --python 3.13 python ../LenBot/scripts/package_plugin.py . /tmp/plugin.zip`。打包取 Git 已跟踪的运行源码和资源，新增文件需先加入 Git；不会收录本机环境、测试或配置。
